# Root control reference checks

Qualify a newly evaluated immutable source against genuine native GitHub runs
before claiming it as the active reference. Local tests establish code behavior;
native runs establish event, approval and cancellation behavior.

- Use a real, nonempty reference change and the existing scoped Release App
  subject preparer. Preserve the exact base, head and selected source.
- Observe a successful complete current-revision review before reusing its
  response. A provider allocation or partial job is not a successful review.
- Convert the unchanged subject to Draft and observe rejection before funding
  or provider execution. A non-cancelled failure must still fail final control.
- Restore Ready and verify the same complete request and original response are
  replayed with no new reservation or provider request. Never reset a budget.
- For a normal Main promotion, leave the native approval waiting, then advance
  its protected Develop head through another normally reviewed change.
- Observe automatic cancellation of the superseded run and a skipped final
  control job. The replacement head needs its own current run and approval.
- Confirm another pull request continues independently; concurrency is scoped
  to the repository and pull request, not to every change in the repository.

Read back the actual run, attempt, head, source and approval after each native
operation. Keep native CI and review history authoritative. Unknown outcomes
permit observation; they do not authorize another funded request or a bypass.
